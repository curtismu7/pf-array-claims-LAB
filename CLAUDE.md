# pf-array-claims-LAB

Tester-tier standalone: "PF Array Claims", the isMemberOf claim-shape use case — a PingFederate-issued token can carry group entitlements as a delimited string or a JSON array, and a group-entitlement policy on an MCP gateway answers differently for each: substring search over the string over-grants to decoy names; the array gives exact membership. Mint panel (both shapes, decoded claims), three simulated cases, "The fix" guide (5 steps) and an IS / IS NOT panel. Structure copied from cedar-in-privilege-LAB.

- Run: `npm ci && npm start` (port 7828 and catalog id D140 provisional are placeholders; the shelf registry has the final say) or `docker compose up --build -d`
- Test: `npm test` (node --test + vitest + repo checks), `npm run doctor`. There is NO real probe here: Real is not available in this lab.
- Rules that bite: mock by default; the Real toggle is DISABLED with a visible reason and `POST /api/mode {"source":"real"}` answers 409 (the server never calls out; netguard + self-test stay on). Loopback-only publish, example group names only (`MCPAccess-<tool>-<level>` pattern, decoy `MCPAccess-Atlan-Read-Extra`), `.example` hosts; the mock token of a run is shown whole and labelled mock-issued (rule 4).
- The claim logic lives in `server/src/claims.js` (mint both shapes, `claimMatches` with the two modes); the door in `server/src/door.js`; scenarios/cases/groups in `server/src/scenarios.js`; "The fix" and IS / IS NOT in `server/src/content.js`. The mock door is NOT a policy engine and decides nothing real; say so wherever it is described.
- The two serialisations are what JSON guarantees (shown live in the Mint panel); the over-grant is computed by this lab's door. Every statement on the page is labelled measured / console text / UNVERIFIED. Never write "verified", "validated" or any claim about a specific product version or tenant behaviour; `test/honesty-text.test.js` fails on them.
- What the mock policy door did (Rule 25; titled through title/basisNote props in `web/src/LabTrace.jsx`, never the default "What Privilege did", and `.lab-trace .gw-lead` is hidden in `web/app.css` because the panel is byte-pinned): `POST /api/run` attaches a `trace` (`server/src/door.js`, decisions `checked` because the mock door computed them). Vendored byte-for-byte, each with a pin file: `web/src/top-menu/*` (top-menu.sha256), `web/src/components/JsonPane.*` (their .sha256), `web/src/gateway-trace/*` and `server/src/gatewayTrace.js` (gateway-trace.sha256), `web/standalone-ui.css` (scripts/standalone-ui.sha256), `test/kit/demo-kit-conformance.mjs` (its .sha256), `scripts/check-no-ai-attribution.sh` (its .sha256). Never hand-edit a pinned file; re-vendor with cp, then re-pin.
- The diagram (rule 17) is diagram-studio/1 data vendored under `web/src/studio-data` (`pf-array-claims-flow`), vendored byte for byte in `web/src/studio-data/` with `studio-data.sha256` (re-vendor, never edit) and looked up by name (`getDiagram`, `web/src/diagram-data.js`); there is no lab-local diagram file. Simulate finds arrows by the boxes they join; refusal is the accent colour. The page never throws on an unreachable server: `postJson` answers status 0 and the page shows the error with a Retry.
- Workspace id (rule 13): the `X-Workspace-Id` request header (1 to 64 of `A-Za-z0-9._-`, else a 400 `bad_workspace`; absent means `default`) keys `state.workspaces` in `server/src/index.js` (at most 100 workspaces, LRU dropped). `web/src/api.js` makes one id per tab (sessionStorage, memory fallback) and sends it on every request, also to `/api/shelf` through ShelfLink.
- customer.config (rule 12): the optional `customer.config.json` is read at start/dev only; the Docker image does not contain it (`.dockerignore`, read-only filesystem).
- Header controls: Help, version, Shelf and Talk track come from the shared TopMenu props; dialogs vendored byte for byte with pin files (`web/src/floating-dialog/*`, `web/src/help-dialog/*`, `web/src/talk-track/*`, `web/src/components/ShelfLink.jsx`); `test/vendored-pins.test.js` and `scripts/repo-checks.mjs` check them. The lab supplies content only: `web/src/helpContent.js` (Help) and `docs/talk-track.md` read at build time by `web/src/talkTrack.js` (a test fails when the doc's shape changes). The version is package.json's, set at build time by `vite.config.js`.
